# Kazumi Web

将 [Kazumi](https://github.com/Predidit/Kazumi) 的番剧浏览和基于规则的观看流程迁移到浏览器，使用 React + Node.js，支持 Docker Compose 一键部署。此目录是独立 Web 工程，不需要 Flutter SDK，也不会修改旁边的原版工程。

## 部署

需要 Docker Engine 和 Docker Compose v2 或更高版本。在本目录运行：

```bash
docker compose up -d --build
```

打开 <http://localhost:3000>。其他设备使用 `http://服务器IP:3000`。首次构建需要访问 npm 和 Docker 镜像仓库。

修改监听地址和端口：

```bash
cp .env.example .env
# 编辑 .env，例如 PORT=8080
docker compose up -d
```

常用维护命令：

```bash
docker compose ps
docker compose logs -f --tail=100 kazumi
docker compose up -d --build          # 更新代码后重新构建
docker compose down                  # 停止服务，保留规则数据
```

容器以非 root 用户运行，根文件系统只读，带健康检查。`kazumi-data` 数据卷保存规则、收藏、观看记录、播放进度、视频缓存和本地番剧元数据库；重新创建容器不会丢失这些数据。首次启动会在后台下载并导入 Bangumi 官方归档，可在「偏好设置 → 本地番剧资料」查看进度。`docker compose down -v` 会删除整个数据卷，请勿将其用作普通停止命令。

## 使用

1. 在「发现」浏览番剧，或搜索番剧名称；「番剧分类」按题材、类型、年份和季度组合筛选，支持按收藏人数、排名或评分排序和翻页；「放送日历」查看每周放送。题材可多选并添加自定义标签，多选标签需同时匹配；类型依据官方归档的平台枚举及标签筛选。点击详情中的标签可进入分类，筛选条件和页码保存在链接中，支持刷新、分享和从详情返回。
2. 打开详情，选择收藏状态，或搜索播放源。也可以直接按名称搜索规则源，不依赖 Bangumi 条目。
3. 选择结果、播放线路和剧集。先快速解析 MP4/HLS；未找到视频时，服务端浏览器运行片源网页并验证视频地址，成功后通过同源代理使用内置播放器。遇到验证码时，在站内弹窗中人工完成验证，再继续搜索、读取剧集或解析播放。失败会显示原因，可重新解析、切换线路或打开原站。
4. 在规则管理中导入原版 Kazumi JSON、规则数组或 `kazumi://` 分享文本，也可从官方规则仓库安装。侧栏「规则管理」显示可更新数量，管理页标出可更新的规则；打开网页、规则变更、回到网页及网页可见时每隔 1 小时检查更新，官方目录缓存 1 小时，没有更新时隐藏数字。已安装列表可单独更新或「更新全部」，导入的同名规则也能从官方目录更新；更新保留启用状态，不降级规则。未收录的自定义规则可重新导入或编辑，批量更新会显示每条失败原因。规则也支持导出和删除。
5. 追番状态、播放进度和历史记录保存在服务器，所有连接同一部署的设备共享；界面主题和自动连播偏好保存在当前浏览器。旧版浏览器数据可在「偏好设置」点击「迁移浏览器旧数据」合并到服务器，也可继续导出和恢复 JSON 备份。
6. 在内置播放器中缓存当前剧集，或点击「选择剧集缓存」，全选当前线路或勾选指定剧集后缓存；在「下载缓存」查看进度、播放已缓存视频、下载到设备，或手动清理单项及全部缓存。

| WebView 嗅探                           | 服务端 Chromium 动态解析 MP4/HLS，支持嵌套播放器和媒体请求会话；解码仍由浏览器完成                  |

这是独立的 Web 移植实现。动态解析可以运行网页 JavaScript 并捕获普通 MP4/HLS 请求，但不保证所有源可用。DRM、私有分片协议、DASH 和浏览器不支持的编码尚未处理，也不执行转码。播放失败时可换源，或使用页面提供的原站链接。

Bangumi 图片通过同源 `/api/image` 加载，服务端缓存在 `DATA_DIR/images`，采用与原版相同的缓存优先策略：先显示已有封面，过期时在后台检查更新，新图取得后自动替换当前页面的封面，刷新失败时继续显示旧封面。刷新有效期遵循上游 `Cache-Control`，未提供时默认 7 天；支持 ETag、Last-Modified 条件请求，上游返回 304 时保留图片文件并更新有效期。浏览器也支持 `stale-while-revalidate`，封面组件在图片加载后检查有效期，仅在过期时等待后台刷新结果，不阻塞已有图片的展示。

缓存及上游校验信息跨重启保留，旧版缓存会在首次访问时后台补齐信息。30 天未使用的图片会被清理，默认最多保留 5000 张，同时保留 5 GiB 的磁盘容量上限，超出后优先淘汰最近最少使用的图片；单张图片最多 5 MiB。

官方归档不包含封面地址：本地条目使用稳定的图片接口引用，直连和 ECH 模式在缓存未命中或后台刷新时通过 Bangumi Next 查询 CDN 地址，再下载或校验图片；镜像模式将图片接口引用直接交给 wsrv.nl，无需服务器先访问 Bangumi。分类、搜索和详情查询不等待封面请求。仅代理 Bangumi 图片域名和图片接口，或由这些地址生成的 wsrv.nl 镜像请求，逐跳检查重定向并校验公网地址、响应类型及图片文件标记，不转发浏览器 Cookie。导入数据中的其他图片地址仍按原地址加载。封面请求方式与 Bangumi API ECH 独立，未缓存图片的可达性仍取决于部署服务器的网络和上游状态。

### 本地番剧资料与更新

默认从 [Bangumi 官方归档](https://github.com/bangumi/Archive)建立 SQLite 元数据库，只导入动画条目及其章节，包含名称、中文名、简介、标签、类型、日期、评分、排名、收藏数量和章节信息。支持中文短词、英文及别名搜索、多标签交集、年份/季度筛选和每页 24 条分页。官方每周发布归档，标签和评分属于快照，可能与网站实时结果不同；新条目需等待后续归档收录，不会在本地详情缺失时偷偷转回官方查询。

首次启动在后台初始化，期间健康检查、规则、收藏和播放接口仍可使用；本地番剧浏览和日历会提示资料尚未就绪。在「偏好设置 → 本地番剧资料」可查看版本、条目数量、下载/导入进度、最近错误，并手动检查更新。默认每 24 小时检查一次官方最新版本，版本校验和未变化时不重复下载；失败后 15 分钟重试。`METADATA_AUTO_UPDATE=false` 可关闭自动初始化与定期检查，仍保留手动更新。

归档以流方式下载到 `DATA_DIR/metadata`，校验声明大小及官方 SHA-256 后，在后台线程导入临时数据库、建立索引并检查完整性，成功后原子切换版本。更新时继续读取旧资料，下载、导入或校验失败均保留原数据库；更新进程意外退出后锁自动释放。保留当前版本及一个前序快照，下载临时文件自动清理。当前归档约 446 MB，本地动画数据库约 114 MiB，建议在数据卷预留至少 2 GiB 更新空间。Node 24 内置 SQLite，无需额外数据库容器。

Docker 已集成自动初始化与定期检查，使用原有 `kazumi-data` 数据卷。更新应用运行 `docker compose up -d --build` 即可。可手动检查或查看状态：

```bash
docker compose exec kazumi npm run metadata:update
docker compose exec kazumi npm run metadata:update -- --status
```

本地开发使用 `npm run metadata:update`，命令会读取 `.env`；常规开发服务器仍通过进程环境变量接收部署配置。也支持离线导入事先下载的官方 ZIP：

```bash
npm run metadata:update -- --file ./dump.zip --version dump-example.zip
# 容器内的 ZIP 应预先放入可写数据卷
docker compose exec kazumi npm run metadata:update -- --file /app/data/dump.zip
```

导入命令不会删除手动提供的 ZIP。归档中的其他作品类型、人物、角色、评论和账号数据不导入。近期热门和放送日历同样走本地数据库，封面继续代理缓存。近期热门筛选近 365 天内开播且日期完整的动画，按归档中的累计收藏人数排序，反映归档热度；官方归档没有实时趋势或收藏增长数据。放送日历按北京时间的本周一至周日，读取正片章节的完整放送日期，同一作品一天只出现一次；只有缺少有效正片日期时才以作品首播日期补充，且不推算每周重复播出。归档缺失的日期和临时延期可能暂未反映，页面会注明资料依据。需要临时恢复原来的远程查询方式，可设置 `METADATA_MODE=remote`；切换模式不会删除本地资料或观看记录。

播放器在「播放信息与诊断」中显示编码、浏览器支持情况和实际加载结果。HLS 在浏览器支持时优先使用 hls.js 扩展播放，兼容 DM84 等来源带图片头的 TS 分片；扩展播放不可用时回退到原生 HLS。HLS 扩展播放使用清单及分片编码信息，原生 HLS 检查主清单，普通视频额外读取最多 256 KiB 前缀以识别 MP4 编码；检查并行执行，不阻塞播放。未提供编码、MP4 元数据位于文件尾部或无法准确识别编码配置时会显示未确定，最终以实际加载为准。错误提示区分访问拒绝、地址失效、资源缺失、网络超时、编码不支持、内容解析、解密和解码失败；编码检查不会增加浏览器解码能力，也不进行转码。

API 规则的 JSONPath 支持字段访问、数组索引与通配符，不执行过滤脚本或递归下降。验证码使用规则中的文本/XPath 配置和有限的常见页面标记检测，服务端不执行规则中的任意 JavaScript 或正则验证码检测。

支持 API 9 的 `searchApiConfig.sourceTemplate`：将搜索响应中的 `sourcePath` 值按 URL 组件编码一次，再替换模板内的 `@source`，例如 `https://example.com/GV@source/`。未设置模板时保留原始条目 ID，兼容 API 章节请求与基于 `baseURL` 的 XPath 详情页读取。

支持原版 `useLegacyParser: true`：从静态或运行时插入的 iframe 查询参数中提取 MP4/HLS 地址，保留媒体自身的签名参数，再验证和代理取流；不要求第三方解析页先成功播放。未开启该字段时沿用普通解析和动态嗅探。

规则设置 `adBlocker: true` 时，在线 HLS 代理、单集缓存和批量缓存均使用原版的广告分片过滤：按 `EXT-X-DISCONTINUITY` 分组，以最长分组为正片参照，过滤相对过短的分组及短片头、片尾。保留密钥和初始化资源，按原始序号补齐 AES-128 隐式 IV，并保留原始字节范围；关闭该字段时不改变分片。主清单和不支持过滤的低延迟扩展保持原样，其普通媒体子清单仍按规则处理。

### 视频下载与缓存

- 打开剧集，完成 MP4/HLS 解析后点击缓存按钮。任务由服务端执行，关闭网页不影响下载；同一来源、同一剧集不会重复创建任务。
- 「选择剧集缓存」支持勾选指定剧集、全选及取消全选，显示已选数量和各集缓存状态。点击「缓存所选」将选中的剧集加入服务端队列，逐集解析并缓存，关闭网页后仍会继续。已完成或正在排队、下载的剧集不可重复选择，缓存失败的剧集可重新勾选；单集失败不影响后续任务，失败原因在「下载缓存」中查看。一次最多加入 200 集，并受现有任务数量和总容量限制。
- 「下载缓存」将同一番剧、同一片源的剧集归入可折叠的列表，按集数排列，并汇总缓存数量、下载状态和占用空间；每集仍可查看进度、播放、保存到设备或删除，也可清理全部缓存。删除进行中的任务会取消下载并释放已写入的文件；不会清除规则、收藏或观看记录。
- 下载列表和播放器缓存面板提供「暂停下载 / 继续下载」。排队或正在解析、下载的任务均可暂停，暂停后停止请求、释放下载名额，保留普通视频的已下载字节和 HLS 已完成的文件，进度仍计入缓存容量。暂停状态跨刷新和服务重启保留，只有点击「继续下载」才重新加入队列；删除任务会清除进度。源站不支持范围请求或没有文件版本标记时，继续下载会重新读取并比对已保存内容，再写入剩余数据，因此仍可能重复传输部分网络流量。
- 点击分组标题旁的「删除整组」，确认后一次删除该剧在当前片源下的全部缓存及任务，并取消组内排队或正在下载的任务；其他番剧、其他片源的缓存会保留。
- 从缓存列表播放任意一集时，播放器会带上同组已缓存完成的剧集，按集数提供选集和「下一话」；开启「自动播放下一话」后可连续播放。排队、下载中或失败的任务不加入播放列表。
- 缓存保存在 `DATA_DIR/downloads`，由访问同一部署的设备共享。已完成任务在服务重启后仍可播放，直接从「下载缓存」进入无需访问原站或保留来源规则。网页仍需连接部署服务器，这不是浏览器离线应用。
- 普通视频可下载原文件到设备。HLS 点播会保存播放清单、子清单、分片、初始化资源和 AES-128 密钥，导出为 `.tar.gz` 文件；解压后使用支持本地 HLS 的播放器打开根播放清单，不会合并或转码为 MP4。含多个清晰度或音轨的清单会缓存其引用的资源。
- 支持 DM84 等来源以图片类型返回、带图片文件头的 HLS 分片，缓存及导出会保留原始字节，站内缓存播放沿用 hls.js 兼容处理；上游返回的网页、JSON 和 SVG 等错误内容仍会被拒绝。
- 在「偏好设置 → 视频下载与缓存」可设置单集下载线程数（1–8，默认 4）。普通视频先探测范围请求，支持时按字节范围并行下载；源站不支持或忽略范围请求时自动改用单连接。HLS 按分片、密钥和初始化资源并行下载，保留清单中的顺序及引用。保存后新开始和重试的任务生效，已在下载的任务继续使用原设置。设置由所有设备共享，保存在 `DATA_DIR/downloads/settings.json`，重启后保留。
- 普通视频在源站支持范围请求并提供强 ETag 或 Last-Modified 时保留字节进度，HLS 保留已完成且通过校验的文件。下载失败或服务重启后，在「下载缓存」点击「继续下载」，会重新解析来源、核对文件版本或 HLS 清单并续传；也可重新选择该集缓存。来源地址、文件版本或清单变化时安全地重新下载。源站不支持续传时重试会从头下载；未完成任务不会作为完整缓存播放，取消或删除任务会清除续传文件。媒体地址和认证信息不会写入续传索引。
- 暂不支持直播、DRM、DASH 和来源站点 iframe 播放器。
- 默认缓存总容量为 10 GiB，同时下载最多 2 集，每集使用所设置的线程数。续传文件也计入容量，达到容量限制时任务会显示失败原因，可先手动清理，再重新缓存。可通过 `VIDEO_CACHE_MAX_GB` 按 G 调整容量上限（1 G = 1 GiB = 1024³ 字节，支持小数，例如 `1.5`）；不会自动删除已有缓存。

设置中的 JSON 数据备份不包含视频文件。迁移完整缓存时，停机后备份并恢复数据目录或 Docker 数据卷。

### 收藏、历史与播放进度

- 收藏状态和最近 200 条观看记录保存在 `DATA_DIR/watch-data.json`，与规则、视频缓存共用持久化数据目录。更新代码后重新构建即可，无需新增数据库或环境变量。
- 所有访问同一部署的设备共享一份记录。打开页面、切回页面以及页面可见时每隔 15 秒读取服务器记录；播放进度每隔约 5 秒保存，暂停、切换剧集、退出播放器和关闭页面时也会尝试保存。读取或保存失败会显示提示。
- 旧版浏览器数据不会自动覆盖服务器。打开原浏览器的「偏好设置」，点击「迁移浏览器旧数据」：新增缺少的收藏，保留服务器已有的收藏状态；同一片源的观看记录按更新时间保留较新的一条。服务器确认保存后才删除对应的浏览器旧数据；迁移失败时原数据保留。
- 「恢复备份」会覆盖服务器的收藏和观看记录，以及本机的界面偏好；「清空记录」会清空服务器的观看记录。这些记录变更会影响连接同一部署的所有设备，界面操作前会提示。

### 在站内完成验证

- 搜索、剧集列表或播放解析遇到验证码后，会弹出「来源网站需要验证」。配置了有效 `captchaImage`、`captchaInput`、`captchaButton` XPath 的规则可直接显示验证码图片与输入框；其他页面显示服务端浏览器的画面。
- 在页面画面上点击或拖动。需要输入文字时，先选中画面里的输入框，再通过弹窗下方发送文字；也可使用回车、退格、切换输入框和滚动按钮。完成后点击「验证完成，继续」，原请求会使用这个浏览器会话继续执行。
- 单次验证任务最多保留 5 分钟，等待人工操作期间暂停普通解析计时。取消、离开当前页面或过期后会释放页面。成功请求的 Cookie、User-Agent 和 localStorage 按当前浏览器会话及规则配置保存在服务端内存中，供后续搜索、选集、播放和批量缓存复用；Cookie 按域名、路径、安全标记及有效期选择，并沿用验证时的 UA。默认最多保留 128 份状态，每份保留 6 小时；规则变更或重启服务后重新验证。验证窗口和保存状态均按当前浏览器会话隔离，前端不会收到源站 Cookie；这不替代部署访问认证。
- 此功能需要启用动态解析并安装 Chromium。它是人工验证入口，不会自动识别答案，也不保证所有来源可用。Cloudflare 明确不支持 Playwright 等自动化浏览器完成生产环境挑战，部分滑块或特殊组件也可能不兼容。参见 [Cloudflare 支持的浏览器环境](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)。
- 携带显式 `Authorization`、`Cookie` 或 `Proxy-Authorization` 请求头的 API 规则仍可正常请求，但暂不进入浏览器验证恢复，避免重定向携带这些凭据。浏览器验证过程中由源站设置的 Cookie 不受此限制。

### 网络设置

在「偏好设置 → 网络设置」填写完整的 HTTP、HTTPS 或 SOCKS5 代理地址，例如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`；需要认证时，单独填写用户名和密码。视频源、番剧图片、Bangumi API、规则仓库、资料归档五类请求共用此地址和认证信息，通过五个独立开关分别启用，没有全局代理开关：

- 「视频源请求代理」：片源搜索、剧集解析、视频流、视频缓存下载，以及动态解析和人工验证浏览器中的请求。右上角「视频代理」快捷开关仅控制这一类，立即保存，不改动图片或 API 设置。
- 「番剧图片请求代理」：Bangumi 原图、wsrv.nl 图片镜像及封面地址查询；不受视频或 API 代理开关影响。
- 「Bangumi API 请求代理」：分类、搜索、详情、章节、日历等 Bangumi API 请求；代理关闭后按 API ECH 开关连接。
- 「规则仓库请求代理」：官方规则目录、规则安装和规则更新，包括 GitHub 原始文件及重定向后的地址。
- 「资料归档下载代理」：官方归档版本检查和 ZIP 下载，适用于自动更新、网页手动更新和 `npm run metadata:update` 命令行更新。

点击「保存网络设置」后新请求立即生效，无需重启，已有连接可能继续使用原设置。五类开关默认关闭；旧全局代理配置升级时会迁移到五个开关，保留原来的启用状态，此后分别保存。已有三类代理设置升级后保留原选择，新增的规则仓库和归档开关默认关闭。重定向和 CDN 请求继续使用原请求所属类别的代理。所选代理不可用时会报错，不会自动切换到直连。

「封面请求方式」可单独选择「镜像 / ECH / 直连」：镜像将 Bangumi 图片 URL 改写为 `https://wsrv.nl/?url=<编码后的原域名、路径和查询参数>`，GIF 追加 `n=-1` 保留动画；ECH 使用原图片 URL 并加密握手，封面地址查询也使用 ECH；直连使用原图片 URL 和普通 HTTPS。新安装默认直连，升级时按旧的 Bangumi ECH 开关保留原封面方式，此后 API 和封面设置分别保存，互不联动。切换方式继续复用已有缓存，未缓存图片及后续刷新使用新方式。只有「番剧图片请求代理」开启时，图片请求才优先使用代理；镜像请求也经由此代理，ECH 模式暂由普通代理通道代替。

「测试连接」使用当前表单的 Bangumi API 代理与 ECH 设置、测试地址发送实际请求，显示 HTTP 状态和耗时，不会保存或启用尚未保存的配置，也不测试封面请求方式。密码不会通过设置接口回传，修改其他选项时留空可保留原密码，也可点击「清除已保存密码」后保存。

代理、API ECH 和封面请求方式由所有设备共享，保存在 `DATA_DIR/network-settings.json`，服务重启后保留；不包含在浏览器 JSON 数据备份中。`npm run metadata:update` 读取已保存的资料归档代理开关及认证配置。浏览器直接打开的原站链接、iframe 播放器及外部图片仍使用访问者自身网络。

代理地址从应用服务器访问：Docker 内的 `127.0.0.1` 指向容器自身。Docker Desktop 访问宿主机代理可填写 `host.docker.internal`；Linux Docker 需在 Compose 服务中添加 `extra_hosts: ["host.docker.internal:host-gateway"]`，并确保宿主机代理监听容器可达的地址。容器之间也可通过同一 Docker 网络中的服务名连接代理。

目标站点仍沿用现有 URL、DNS 与重定向校验：先在服务器解析并校验目标地址，再将选定的 IP 交给代理，保留原始 HTTP Host 和 HTTPS TLS 校验。默认继续拒绝私网目标；配置的代理服务器本身允许使用本机或局域网地址。DNS 查询继续使用服务器 DNS 或已配置的 DoH，并不交给代理解析。

## 数据和网络

- 服务端保存规则、收藏、观看记录、播放进度和视频缓存，访问同一部署的设备共享这些数据。界面偏好按浏览器保存；没有账号隔离。
- 番剧资料来自 Bangumi；规则来自用户导入或上游 KazumiRules。第三方服务不可达时界面会显示错误，页面没有伪造的番剧或播放数据。
- 服务端代理站点请求及媒体资源，处理跨域和防盗链请求头。HLS 的子清单、分片和密钥地址会重写为同源代理地址。
- 已适配 DM84 使用的 HHJX 解析接口和 7sefun 的 ndx 播放线路：服务端取得真实 MP4/HLS 后交给内置播放器，移动设备通过同源媒体代理取流。HHJX 媒体不继承站点 Referer，以兼容其 CDN 的请求头要求。
- MacCMS 规则中解码得到的 HTTP 播放页可交给动态解析，支持 aafun/月之祠嵌套的稀饭 Next 播放页；原站包装播放器未取得视频时，在同一会话中尝试嵌套页。原播放页仍运行，以兼容需要站点解析接口的线路。不透明播放标识不会被误当成相对网页地址。
- 动态解析保留服务端媒体验证；单个候选验证失败后继续等待其他候选，直到整体解析超时，错误中保留最近一次验证失败原因。已捕获候选的验证失败或验证超时不会触发人工验证窗口，页面实际出现验证码时仍可人工完成验证。
- 动态解析按需启动并复用 Chromium，默认同时运行最多 2 个任务，每个任务最多保留原页与一个解码后的嵌套页，普通解析每次最多 20 秒；未进入验证时片源请求总上限 45 秒，退出页面会取消请求。人工验证期间保留页面并占用一个任务名额，完成后继续解析，最终关闭页面，播放流量交给媒体代理。浏览器依赖已打包进 Docker 镜像，首次构建会下载浏览器和系统依赖。
- 动态媒体的 Cookie 和授权请求头保存在有容量与有效期限制的服务端内存会话中，前端只收到签名会话引用；Cookie 按目标域名和路径选择。服务重启后需重新打开剧集。浏览器子资源和 HTTPS 隧道通过校验并绑定公网 IP 的本地出口，沿用私网保护和可选 DoH。
- 默认拒绝代理访问本机、私网、链路本地和云元数据地址，并校验重定向目标。
- 默认适用于个人/家庭局域网部署，没有多用户登录和权限隔离。若要公开部署，请在前置反向代理配置 HTTPS 和访问认证，避免陌生人修改共享规则或消耗代理流量。

JSON 数据备份不包含服务端规则，迁移时应同时导出规则，或停机后备份整个数据目录。备份包含观看记录，请自行妥善保存。

## 本地开发

需要 Node.js 24+：

```bash
npm ci
npx playwright install --with-deps --only-shell chromium
npm run dev
```

前端：<http://localhost:5173>；后端：<http://localhost:3000>。Vite 将 `/api` 转发至后端。

如果开发机的 3000 端口已被占用，执行 `API_PORT=3100 npm run dev`，前后端代理会一起使用新端口，前端仍在 5173。开发模式不自动读取部署用的 `.env`；可通过进程环境变量传入配置，例如 `DNS_OVER_HTTPS_URL=https://1.1.1.1/dns-query npm run dev`。也可复制 `.env.example` 为 `.env`，按需取消注释并修改配置，再用 `node --env-file=.env scripts/dev.mjs` 启动。`npm run dev` 使用 `API_PORT` 设置后端端口，会覆盖 `PORT`。

npm test             # 前端、后端和共享逻辑的全部 Node.js 测试

npm run test:server   # 单独运行后端单元与集成测试
npm run test:shared   # 单独运行前后端共享逻辑测试

### 测试目录

- `test/frontend/`：直接验证 `src/` 中前端模块的逻辑，包含媒体探测、播放错误、播放器控制、API 请求与验证会话队列测试。
- `test/server/`：验证 `server/` 的规则、HTTP 接口、存储、缓存、媒体代理和浏览器解析；后端专用的归档及规则夹具放在 `test/server/fixtures/`。
- `test/shared/`：直接验证根目录 `shared/` 中前后端复用的纯逻辑，目前包含图片地址处理测试。后端测试使用共享工具构造数据时，仍按被测服务归属放在后端目录。
- `test/e2e/`：Playwright 浏览器及生产 HTTP 流程测试，包含启动脚本和模拟上游服务，测试时使用临时数据目录。
- `test/fixtures/media/`：前端、后端和端到端测试共用的 MP4、HLS 清单与分片；生成方法见 `test/fixtures/README.md`。
- `native/ech/main_test.go`：保留 Go 测试与源码同目录的惯例，在 `native/ech` 下执行 `go test ./...`。

`npm test` 汇总前三类 Node.js 测试，支持各目录中的嵌套 `*.test.js`；`npm run check` 运行这些测试并构建前端。端到端测试继续单独运行 `npm run test:e2e`。CI 的离线元数据容器测试只读挂载 `test/`，执行 `test/server/local-metadata.test.js`。

### 前端代码结构

- `src/App.jsx`：应用布局、Hash 导航与全局状态协调。
- `src/features/`：按功能组织番剧浏览、收藏、历史、下载缓存、片源搜索、规则、设置、播放器和人工验证；功能内部的组件与逻辑放在一起。
- `src/components/`：跨功能使用的弹窗、提示、标题、海报网格和缓存图片组件。
- `src/hooks/`：通用请求、本机偏好与观看记录同步的 React hooks。
- `src/lib/`：API 请求、验证会话通信与队列、格式化和 JSON 文件导出工具；前后端共用的数据约定仍放在根目录 `shared/`。
- `src/styles.css`：样式唯一入口，按原有层叠顺序导入 `src/styles/` 中的功能样式。跨功能的响应式覆盖集中在 `responsive.css`，调整导入顺序前需检查桌面、移动端和深色主题。

新增页面放入对应的功能目录，由 `App.jsx` 接入导航；公共组件和工具避免依赖具体功能页面。验证弹窗通过 `src/lib/verification.js` 订阅待处理请求，与 API 客户端共享通信状态，通信层可直接在 Node.js 中测试。整理前端后运行 `npm run check` 和 `npm run test:e2e`，播放器基础逻辑的测试位于 `test/frontend/playback.test.js`。

### 后端代码结构

- `server/index.js`：命令行入口，负责监听端口、启动资料更新和处理退出信号；仍导出 `createApp`，供测试及程序调用。
- `server/app.js`：按原有顺序初始化服务、装配中间件和路由，并统一关闭服务资源；`createApp(options)` 的配置和返回值保持一致。
- `server/routes.js`：集中注册各业务路由，保留路由注册顺序；健康检查和图片代理入口直接注册，图片请求的处理仍由图片缓存模块负责。
- `server/modules/`：按规则、观看记录、番剧资料、图片缓存、播放解析、人工验证和下载缓存归拢模块；业务目录中的 `routes.js` 处理 HTTP 输入输出，服务、存储和解析逻辑放在同目录。
- `server/middleware/`：请求安全校验、每实例 API 限流、静态文件与页面回退、API 404 和统一错误响应。装配顺序为安全校验、JSON 解析、限流、业务路由、API 404、前端文件与回退、错误处理。
- `server/lib/`：HTTP 客户端、网络地址校验、ECH 通道、浏览器出口代理与请求参数校验。
- `server/defaults/`：首次启动使用的来源规则；后端测试位于 `test/server/`，包含中间件顺序、静态页面回退和应用实例隔离的回归测试。

新增接口放入对应业务目录，通过 `server/routes.js` 接入；限流计数、规则目录缓存和验证任务等状态由各应用实例持有。调整后运行 `npm run check` 和 `npm run test:e2e`。

#### Compose 常用配置

以下变量已在 `compose.yaml` 中接入，修改 `.env` 后执行 `docker compose up -d` 即可应用。

| 变量                             | 默认值       | 用途                                                                                            |
| -------------------------------- | ------------ | ----------------------------------------------------------------------------------------------- |
| `HOST_BIND`                      | `0.0.0.0`    | 宿主机监听地址；局域网访问保留默认值，仅本机访问设为 `127.0.0.1`；仅用于 Compose                |
| `PORT`                           | `3000`       | Compose 的宿主机访问端口，容器内部固定为 `3000`；本地 `npm start` 用作 Node 监听端口            |
| `VIDEO_CACHE_MAX_GB`             | `10`         | 视频缓存总容量上限（GiB，1 GiB = 1024³ 字节，支持小数且必须大于 0）；不会自动删除已有缓存       |
| `IMAGE_CACHE_MAX_BYTES`          | `5368709120` | 图片磁盘缓存上限（字节，默认 5 GiB）；`0` 关闭图片磁盘缓存                                      |
| `METADATA_MODE`                  | `local`      | `local` 使用本地归档，`remote` 使用远程查询；切换模式保留本地数据                               |
| `METADATA_AUTO_UPDATE`           | `true`       | 本地模式下首次后台初始化并定期检查归档；`false` 关闭自动更新，仍允许手动更新                    |
| `METADATA_UPDATE_INTERVAL_HOURS` | `24`         | 自动检查间隔（小时，1–720）；更新失败后 15 分钟重试                                             |
| `DNS_OVER_HTTPS_URL`             | 空           | 可选 DNS JSON 查询端点，例如 `https://1.1.1.1/dns-query`；留空使用系统 DNS，仍校验并绑定公网 IP |
| `DYNAMIC_RESOLVER`               | `true`       | 服务端浏览器解析及人工验证；`false` 保留快速解析与网页播放器回退                                |
| `DYNAMIC_RESOLVER_TIMEOUT_MS`    | `20000`      | 单次浏览器解析超时（毫秒，正数，最大 30000）；人工验证等待时间另计                              |
| `DYNAMIC_RESOLVER_CONCURRENCY`   | `2`          | 浏览器任务并发上限（整数，1–4）；等待人工验证的任务也占用名额                                   |

#### 其他服务端配置

以下变量由 Node 服务读取，但 Compose 不会自动从 `.env` 传入这些值。本地运行时可使用上面的 `--env-file` 命令；Docker 中需显式配置 `environment`。

| 变量                            | 默认值                                                                                             | 用途                                                                                                                                    |
| ------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `HOST`                          | `0.0.0.0`                                                                                          | Node 监听地址；Compose 固定为 `0.0.0.0`，宿主机监听地址通过 `HOST_BIND` 设置                                                            |
| `DATA_DIR`                      | 项目根目录下的 `data`                                                                              | 规则、收藏、观看记录、播放进度、图片、视频缓存和元数据库目录；相对路径按进程工作目录解析；Compose 固定为 `/app/data` 并挂载数据卷       |
| `METADATA_ARCHIVE_MANIFEST_URL` | [官方 `aux/latest.json`](https://raw.githubusercontent.com/bangumi/Archive/master/aux/latest.json) | 归档版本清单地址，需返回官方格式的 ZIP URL、大小、名称和 SHA-256                                                                        |
| `BANGUMI_API_URL`               | `https://api.bgm.tv`                                                                               | Bangumi API 基址，主要用于远程元数据模式                                                                                                |
| `BANGUMI_NEXT_URL`              | `https://next.bgm.tv`                                                                              | Bangumi Next API 基址，用于远程元数据模式，也用于本地模式的封面地址查询                                                                 |
| `BANGUMI_USER_AGENT`            | 内置 `KazumiWeb/1.0` 标识，完整值见 `.env.example`                                                 | 元数据服务请求 Bangumi 时使用的 User-Agent；不影响片源请求或封面地址查询                                                                |
| `RULES_REPOSITORY`              | [KazumiRules 原始文件目录](https://raw.githubusercontent.com/Predidit/KazumiRules/main/)           | 规则目录及 JSON 文件的基址，需提供 `index.json` 和对应规则文件                                                                          |
| `ALLOW_PRIVATE_NETWORK`         | `false`                                                                                            | 允许服务端请求本机、私网和保留地址，仅可信内网源或隔离测试环境按需开启；Compose 固定为 `false`                                          |
| `MEDIA_SECRET`                  | 每次启动随机生成                                                                                   | 媒体代理 URL 签名密钥，留空即可；如需固定值，应自行生成随机密钥。固定密钥不会持久化动态媒体会话，重启后仍需重新打开剧集；它不是登录密码 |

例如，要在 Docker 中修改 Bangumi API 基址，先在 `.env` 中取消注释并修改 `BANGUMI_API_URL`，再新建 `compose.override.yaml`：

```yaml
services:
  kazumi:
    environment:
      BANGUMI_API_URL: '${BANGUMI_API_URL:-https://api.bgm.tv}'
```

其他高级变量按同样方式添加，也可直接修改 `compose.yaml` 的 `environment`。运行 `docker compose config` 检查最终配置，再执行 `docker compose up -d` 应用。`HOST`、容器内部的 `PORT` 和 `DATA_DIR` 与现有端口映射、健康检查和数据卷配置配套；修改宿主机地址及端口使用 `HOST_BIND` / `PORT`。

#### 本地开发与测试配置

这些变量不传入 Compose 容器，通常直接放在命令前，例如 `API_PORT=3100 npm run dev` 或 `BASE_URL=http://localhost:8080 npm run smoke`。

| 变量               | 默认值                  | 用途                                                                             |
| ------------------ | ----------------------- | -------------------------------------------------------------------------------- |
| `API_PORT`         | `3000`                  | `npm run dev` 的后端端口，同时供 Vite 代理使用；覆盖 `PORT`，前端端口仍为 `5173` |
| `BASE_URL`         | `http://localhost:3000` | `npm run smoke` 检查的运行中实例地址                                             |
| `SMOKE_LIVE`       | `false`（未设置）       | `true` 让 smoke 额外检查实际番剧资料和规则仓库，需准备好元数据及上游网络         |
| `E2E_PORT`         | `4173`                  | Playwright 测试应用端口；测试使用临时数据目录                                    |
| `E2E_FIXTURE_PORT` | `4174`                  | Playwright 模拟上游服务端口，需与 `E2E_PORT` 不同                                |

若开启了 TUN/Fake-IP DNS，域名可能解析为 `198.18.x.x`，页面会提示「域名解析到私有或保留网络地址」。在 `.env` 设置 `DNS_OVER_HTTPS_URL=https://1.1.1.1/dns-query` 后重新运行 `docker compose up -d`，不必关闭内网访问保护。DNS 查询将由所配置的解析服务处理。

API ECH 默认关闭。在「偏好设置 → 网络设置」打开「启用 Bangumi API ECH」；封面使用 ECH 时，单独将「封面请求方式」选为「ECH」。两者共用「ECH DNS 地址」（默认 `https://1.1.1.1/dns-query`），点击「保存网络设置」后即时生效，无需重启。ECH 设置不再读取环境变量。Docker 已内置辅助程序；本地开发先运行 `npm run build:ech`（需要 Go 1.23 或更新版本），工具固定放在项目的 `bin/kazumi-ech`（Windows 为 `bin/kazumi-ech.exe`）。

ECH 辅助程序使用 Go 标准库 TLS，只有 `api.bgm.tv`、`next.bgm.tv`、`lain.bgm.tv` 的 HTTPS 默认端口请求会进入此通道。和原版一样，从 `crypto.cloudflare.com` 的 HTTPS DNS 记录取得 Cloudflare 的共享 ECH 配置；目标地址通过 DoH 解析、校验后绑定到连接，不关闭证书验证。每次响应必须确认 ECH 被服务端接受；失败时报告错误，不自动退回普通 TLS。重定向仍交给 Node 逐跳校验和移除跨域凭据。请求体上限为 1 MiB，响应上限为 8 MiB，不处理视频流。

运行 `npm run check:ech` 可对同一组默认分类参数比较直连与 ECH，输出 HTTP 状态、耗时、条目数量和 `echAccepted`；使用已保存的 ECH DNS 地址，诊断时忽略代理和 ECH 开关，不修改设置。本地会读取部署用的 `.env` 以确定数据目录等服务端配置。Docker 中可运行 `docker compose exec kazumi npm run check:ech`。这是实时网络诊断，不属于离线测试；ECH 分类请求失败时退出码为 1。ECH 成功协商不代表上游一定及时响应，分类超时仍可能出现在握手完成之后。

## 常见问题

**网页能打开，番剧或规则列表加载失败？** 本地资料模式下，先在「偏好设置」查看首次导入是否完成及最近更新错误；已导入的分类、搜索、详情、近期热门和日历不依赖上游接口。归档下载和规则仓库仍需要服务器访问 GitHub；未缓存封面需要服务器访问 Bangumi。浏览器可以联网不代表 Docker 容器可以访问同一服务。

**能看到剧集，但视频不能播放？** 查看播放器显示的解析或播放错误。服务端会尝试动态 MP4/HLS 解析；验证码、源站限制或不支持的编码仍可能导致失败。可重新解析、换线或打开原站。本地开发提示浏览器未安装时，运行上面的 Chromium 安装命令。

**Mac 能播，iPhone/iPad 黑屏或转圈？** 更新部署后重新打开剧集，让视频通过服务端解析和同源代理。DM84 的 HHJX 和 7sefun 的 ndx 线路保留快速适配，其他网页线路会尝试浏览器解析。若关闭动态解析而回退到「来源站点播放器」，视频仍由设备直连第三方站点，可能受设备网络和源站限制。

**换设备后没有追番和历史？** 确认设备连接的是同一部署，且服务器使用原来的数据目录或数据卷。旧版数据保存在原浏览器中，需要在原浏览器的「偏好设置」点击「迁移浏览器旧数据」，或恢复先前导出的 JSON 备份。迁移完成后，清理浏览器数据不会删除服务器记录。

**规则数据丢失？** 确认使用同一 Compose 项目名及其数据卷。不要执行 `down -v`。可从先前导出的规则恢复。
