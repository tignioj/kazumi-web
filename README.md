# Kazumi Web

将 [Kazumi](https://github.com/Predidit/Kazumi) 的番剧浏览和基于规则的观看流程迁移到浏览器，使用 React + Node.js，支持 Docker Compose 一键部署。此目录是独立 Web 工程，不需要 Flutter SDK，也不会修改旁边的原版工程。

## 部署

需要 Docker Engine 和 Docker Compose v2 或更高版本。在本目录运行：

```bash
docker compose up -d --build
```

打开 <http://localhost:3000>。其他设备使用 `http://服务器IP:3000`。首次构建需要访问 npm 和 Docker 镜像仓库。

修改监听地址和端口：

```bash
cp .env.example .env
# 编辑 .env，例如 PORT=8080
docker compose up -d
```

常用维护命令：

```bash
docker compose ps
docker compose logs -f --tail=100 kazumi
docker compose up -d --build          # 更新代码后重新构建
docker compose down                  # 停止服务，保留规则数据
```

容器以非 root 用户运行，根文件系统只读，带健康检查。`kazumi-data` 数据卷保存规则、收藏、观看记录、播放进度、视频缓存和本地番剧元数据库；重新创建容器不会丢失这些数据。首次启动会在后台下载并导入 Bangumi 官方归档，可在「偏好设置 → 本地番剧资料」查看进度。`docker compose down -v` 会删除整个数据卷，请勿将其用作普通停止命令。

## 使用

1. 在「发现」浏览番剧，或搜索番剧名称；「番剧分类」按题材、类型、年份和季度组合筛选，支持按收藏人数、排名或评分排序和翻页；「放送日历」查看每周放送。题材可多选并添加自定义标签，多选标签需同时匹配；类型依据官方归档的平台枚举及标签筛选。点击详情中的标签可进入分类，筛选条件和页码保存在链接中，支持刷新、分享和从详情返回。
2. 打开详情，选择收藏状态，或搜索播放源。也可以直接按名称搜索规则源，不依赖 Bangumi 条目。
3. 选择结果、播放线路和剧集。先快速解析 MP4/HLS；未找到视频时，服务端浏览器运行片源网页并验证视频地址，成功后通过同源代理使用内置播放器。遇到验证码时，在站内弹窗中人工完成验证，再继续搜索、读取剧集或解析播放。失败会显示原因，可重新解析、切换线路或打开原站。
4. 在规则管理中导入原版 Kazumi JSON、规则数组或 `kazumi://` 分享文本，也可从官方规则仓库安装。侧栏「规则管理」显示可更新数量，管理页标出可更新的规则；打开网页、规则变更、回到网页及网页可见时每隔 1 小时检查更新，官方目录缓存 1 小时，没有更新时隐藏数字。已安装列表可单独更新或「更新全部」，导入的同名规则也能从官方目录更新；更新保留启用状态，不降级规则。未收录的自定义规则可重新导入或编辑，批量更新会显示每条失败原因。规则也支持导出和删除。
5. 追番状态、播放进度和历史记录保存在服务器，所有连接同一部署的设备共享；界面主题和自动连播偏好保存在当前浏览器。旧版浏览器数据可在「偏好设置」点击「迁移浏览器旧数据」合并到服务器，也可继续导出和恢复 JSON 备份。
6. 在内置播放器中缓存当前剧集，在「下载缓存」查看进度、播放已缓存视频、下载到设备，或手动清理单项及全部缓存。

这是独立的 Web 移植实现。动态解析可以运行网页 JavaScript 并捕获普通 MP4/HLS 请求，但不保证所有源可用。DRM、私有分片协议、DASH 和浏览器不支持的编码尚未处理，也不执行转码。播放失败时可换源，或使用页面提供的原站链接。

Bangumi 图片通过同源 `/api/image` 加载，服务端缓存在 `DATA_DIR/images`，采用与原版相同的缓存优先策略：先显示已有封面，过期时在后台检查更新，新图取得后自动替换当前页面的封面，刷新失败时继续显示旧封面。刷新有效期遵循上游 `Cache-Control`，未提供时默认 7 天；支持 ETag、Last-Modified 条件请求，上游返回 304 时保留图片文件并更新有效期。浏览器也支持 `stale-while-revalidate`，封面组件在图片加载后检查有效期，仅在过期时等待后台刷新结果，不阻塞已有图片的展示。

缓存及上游校验信息跨重启保留，旧版缓存会在首次访问时后台补齐信息。30 天未使用的图片会被清理，默认最多保留 200 张，同时保留 256 MiB 的磁盘容量上限，超出后优先淘汰最近最少使用的图片；单张图片最多 5 MiB。

官方归档不包含封面地址：本地条目使用稳定的图片接口引用，在缓存未命中或后台刷新时通过 Bangumi Next 查询 CDN 地址，再下载或校验图片；分类、搜索和详情查询不等待封面请求。仅代理 Bangumi 图片域名和图片接口，逐跳检查重定向并校验公网地址、响应类型及图片文件标记，不转发浏览器 Cookie。导入数据中的其他图片地址仍按原地址加载。可选的 Bangumi ECH 通道见下文，未缓存图片的可达性仍取决于部署服务器的网络和上游状态。

### 本地番剧资料与更新

默认从 [Bangumi 官方归档](https://github.com/bangumi/Archive)建立 SQLite 元数据库，只导入动画条目及其章节，包含名称、中文名、简介、标签、类型、日期、评分、排名、收藏数量和章节信息。支持中文短词、英文及别名搜索、多标签交集、年份/季度筛选和每页 24 条分页。官方每周发布归档，标签和评分属于快照，可能与网站实时结果不同；新条目需等待后续归档收录，不会在本地详情缺失时偷偷转回官方查询。

首次启动在后台初始化，期间健康检查、规则、收藏和播放接口仍可使用；本地番剧浏览和日历会提示资料尚未就绪。在「偏好设置 → 本地番剧资料」可查看版本、条目数量、下载/导入进度、最近错误，并手动检查更新。默认每 24 小时检查一次官方最新版本，版本校验和未变化时不重复下载；失败后 15 分钟重试。`METADATA_AUTO_UPDATE=false` 可关闭自动初始化与定期检查，仍保留手动更新。

归档以流方式下载到 `DATA_DIR/metadata`，校验声明大小及官方 SHA-256 后，在后台线程导入临时数据库、建立索引并检查完整性，成功后原子切换版本。更新时继续读取旧资料，下载、导入或校验失败均保留原数据库；更新进程意外退出后锁自动释放。保留当前版本及一个前序快照，下载临时文件自动清理。当前归档约 446 MB，本地动画数据库约 114 MiB，建议在数据卷预留至少 2 GiB 更新空间。Node 24 内置 SQLite，无需额外数据库容器。

Docker 已集成自动初始化与定期检查，使用原有 `kazumi-data` 数据卷。更新应用运行 `docker compose up -d --build` 即可。可手动检查或查看状态：

```bash
docker compose exec kazumi npm run metadata:update
docker compose exec kazumi npm run metadata:update -- --status
```

本地开发使用 `npm run metadata:update`，命令会读取 `.env`；常规开发服务器仍通过进程环境变量接收部署配置。也支持离线导入事先下载的官方 ZIP：

```bash
npm run metadata:update -- --file ./dump.zip --version dump-example.zip
# 容器内的 ZIP 应预先放入可写数据卷
docker compose exec kazumi npm run metadata:update -- --file /app/data/dump.zip
```

导入命令不会删除手动提供的 ZIP。归档中的其他作品类型、人物、角色、评论和账号数据不导入。近期热门和放送日历同样走本地数据库，封面继续代理缓存。近期热门筛选近 365 天内开播且日期完整的动画，按归档中的累计收藏人数排序，反映归档热度；官方归档没有实时趋势或收藏增长数据。放送日历按北京时间的本周一至周日，读取正片章节的完整放送日期，同一作品一天只出现一次；只有缺少有效正片日期时才以作品首播日期补充，且不推算每周重复播出。归档缺失的日期和临时延期可能暂未反映，页面会注明资料依据。需要临时恢复原来的远程查询方式，可设置 `METADATA_MODE=remote`；切换模式不会删除本地资料或观看记录。

播放器在「播放信息与诊断」中显示编码、浏览器支持情况和实际加载结果。HLS 在浏览器支持时优先使用 hls.js 扩展播放，兼容 DM84 等来源带图片头的 TS 分片；扩展播放不可用时回退到原生 HLS。HLS 扩展播放使用清单及分片编码信息，原生 HLS 检查主清单，普通视频额外读取最多 256 KiB 前缀以识别 MP4 编码；检查并行执行，不阻塞播放。未提供编码、MP4 元数据位于文件尾部或无法准确识别编码配置时会显示未确定，最终以实际加载为准。错误提示区分访问拒绝、地址失效、资源缺失、网络超时、编码不支持、内容解析、解密和解码失败；编码检查不会增加浏览器解码能力，也不进行转码。

API 规则的 JSONPath 支持字段访问、数组索引与通配符，不执行过滤脚本或递归下降。验证码使用规则中的文本/XPath 配置和有限的常见页面标记检测，服务端不执行规则中的任意 JavaScript 或正则验证码检测。

支持 API 9 的 `searchApiConfig.sourceTemplate`：将搜索响应中的 `sourcePath` 值按 URL 组件编码一次，再替换模板内的 `@source`，例如 `https://example.com/GV@source/`。未设置模板时保留原始条目 ID，兼容 API 章节请求与基于 `baseURL` 的 XPath 详情页读取。

### 视频下载与缓存

- 打开剧集，完成 MP4/HLS 解析后点击缓存按钮。任务由服务端执行，关闭网页不影响下载；同一来源、同一剧集不会重复创建任务。
- 「下载缓存」显示任务状态、进度和容量，可播放已完成的缓存，删除单项任务或清理全部缓存。删除进行中的任务会取消下载并释放已写入的文件；不会清除规则、收藏或观看记录。
- 缓存保存在 `DATA_DIR/downloads`，由访问同一部署的设备共享。已完成任务在服务重启后仍可播放，直接从「下载缓存」进入无需访问原站或保留来源规则。网页仍需连接部署服务器，这不是浏览器离线应用。
- 普通视频可下载原文件到设备。HLS 点播会保存播放清单、子清单、分片、初始化资源和 AES-128 密钥，导出为 `.tar.gz` 文件；解压后使用支持本地 HLS 的播放器打开根播放清单，不会合并或转码为 MP4。含多个清晰度或音轨的清单会缓存其引用的资源。
- 暂不支持直播、DRM、DASH 和来源站点 iframe 播放器。下载失败或服务重启时尚未完成的任务不会作为完整缓存播放；重新打开剧集后可重试，不支持断点续传。
- 默认缓存总容量为 10 GiB，同时下载最多 2 项。达到容量限制时任务会显示失败原因，可先手动清理，再重新缓存。可通过 `VIDEO_CACHE_MAX_BYTES` 调整字节上限；不会自动删除已有缓存。

设置中的 JSON 数据备份不包含视频文件。迁移完整缓存时，停机后备份并恢复数据目录或 Docker 数据卷。

### 收藏、历史与播放进度

- 收藏状态和最近 200 条观看记录保存在 `DATA_DIR/watch-data.json`，与规则、视频缓存共用持久化数据目录。更新代码后重新构建即可，无需新增数据库或环境变量。
- 所有访问同一部署的设备共享一份记录。打开页面、切回页面以及页面可见时每隔 15 秒读取服务器记录；播放进度每隔约 5 秒保存，暂停、切换剧集、退出播放器和关闭页面时也会尝试保存。读取或保存失败会显示提示。
- 旧版浏览器数据不会自动覆盖服务器。打开原浏览器的「偏好设置」，点击「迁移浏览器旧数据」：新增缺少的收藏，保留服务器已有的收藏状态；同一片源的观看记录按更新时间保留较新的一条。服务器确认保存后才删除对应的浏览器旧数据；迁移失败时原数据保留。
- 「恢复备份」会覆盖服务器的收藏和观看记录，以及本机的界面偏好；「清空记录」会清空服务器的观看记录。这些记录变更会影响连接同一部署的所有设备，界面操作前会提示。

### 在站内完成验证

- 搜索、剧集列表或播放解析遇到验证码后，会弹出「来源网站需要验证」。配置了有效 `captchaImage`、`captchaInput`、`captchaButton` XPath 的规则可直接显示验证码图片与输入框；其他页面显示服务端浏览器的画面。
- 在页面画面上点击或拖动。需要输入文字时，先选中画面里的输入框，再通过弹窗下方发送文字；也可使用回车、退格、切换输入框和滚动按钮。完成后点击「验证完成，继续」，原请求会使用这个浏览器会话继续执行。
- 单次验证任务最多保留 5 分钟，等待人工操作期间暂停普通解析计时。取消、离开当前页面或过期后会释放会话；重启服务后需重新验证。验证 Cookie 留在服务端，验证窗口按当前浏览器的会话隔离；这不替代部署访问认证。
- 此功能需要启用动态解析并安装 Chromium。它是人工验证入口，不会自动识别答案，也不保证所有来源可用。Cloudflare 明确不支持 Playwright 等自动化浏览器完成生产环境挑战，部分滑块或特殊组件也可能不兼容。参见 [Cloudflare 支持的浏览器环境](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/)。
- 携带显式 `Authorization`、`Cookie` 或 `Proxy-Authorization` 请求头的 API 规则仍可正常请求，但暂不进入浏览器验证恢复，避免重定向携带这些凭据。浏览器验证过程中由源站设置的 Cookie 不受此限制。

## 数据和网络

- 服务端保存规则、收藏、观看记录、播放进度和视频缓存，访问同一部署的设备共享这些数据。界面偏好按浏览器保存；没有账号隔离。
- 番剧资料来自 Bangumi；规则来自用户导入或上游 KazumiRules。第三方服务不可达时界面会显示错误，页面没有伪造的番剧或播放数据。
- 服务端代理站点请求及媒体资源，处理跨域和防盗链请求头。HLS 的子清单、分片和密钥地址会重写为同源代理地址。
- 已适配 DM84 使用的 HHJX 解析接口和 7sefun 的 ndx 播放线路：服务端取得真实 MP4/HLS 后交给内置播放器，移动设备通过同源媒体代理取流。HHJX 媒体不继承站点 Referer，以兼容其 CDN 的请求头要求。
- MacCMS 规则中解码得到的 HTTP 播放页可交给动态解析，支持 aafun/月之祠嵌套的稀饭 Next 播放页；原站包装播放器未取得视频时，在同一会话中尝试嵌套页。原播放页仍运行，以兼容需要站点解析接口的线路。不透明播放标识不会被误当成相对网页地址。
- 动态解析按需启动并复用 Chromium，默认同时运行最多 2 个任务，每个任务最多保留原页与一个解码后的嵌套页，普通解析每次最多 20 秒；未进入验证时片源请求总上限 45 秒，退出页面会取消请求。人工验证期间保留页面并占用一个任务名额，完成后继续解析，最终关闭页面，播放流量交给媒体代理。浏览器依赖已打包进 Docker 镜像，首次构建会下载浏览器和系统依赖。
- 动态媒体的 Cookie 和授权请求头保存在有容量与有效期限制的服务端内存会话中，前端只收到签名会话引用；Cookie 按目标域名和路径选择。服务重启后需重新打开剧集。浏览器子资源和 HTTPS 隧道通过校验并绑定公网 IP 的本地出口，沿用私网保护和可选 DoH。
- 默认拒绝代理访问本机、私网、链路本地和云元数据地址，并校验重定向目标。
- 默认适用于个人/家庭局域网部署，没有多用户登录和权限隔离。若要公开部署，请在前置反向代理配置 HTTPS 和访问认证，避免陌生人修改共享规则或消耗代理流量。

JSON 数据备份不包含服务端规则，迁移时应同时导出规则，或停机后备份整个数据目录。备份包含观看记录，请自行妥善保存。

若开启了 TUN/Fake-IP DNS，域名可能解析为 `198.18.x.x`，页面会提示「域名解析到私有或保留网络地址」。在 `.env` 设置 `DNS_OVER_HTTPS_URL=https://1.1.1.1/dns-query` 后重新运行 `docker compose up -d`，不必关闭内网访问保护。DNS 查询将由所配置的解析服务处理。

ECH 默认关闭。需要试用时，在部署用的 `.env` 中设置 `BANGUMI_ECH=true`，然后运行 `docker compose up -d --build`。本地开发先运行 `npm run build:ech`（需要 Go 1.23 或更新版本），再用 `BANGUMI_ECH=true npm run dev` 启动；开发模式的设置仍通过进程环境变量传入。

ECH 辅助程序使用 Go 标准库 TLS，只有 `api.bgm.tv`、`next.bgm.tv`、`lain.bgm.tv` 的 HTTPS 默认端口请求会进入此通道。和原版一样，从 `crypto.cloudflare.com` 的 HTTPS DNS 记录取得 Cloudflare 的共享 ECH 配置；目标地址通过 DoH 解析、校验后绑定到连接，不关闭证书验证。每次响应必须确认 ECH 被服务端接受；失败时报告错误，不自动退回普通 TLS。重定向仍交给 Node 逐跳校验和移除跨域凭据。请求体上限为 1 MiB，响应上限为 8 MiB，不处理视频流。

运行 `npm run check:ech` 可对同一组默认分类参数比较直连与 ECH，输出 HTTP 状态、耗时、条目数量和 `echAccepted`；本地会读取部署用的 `.env`。Docker 中可运行 `docker compose exec kazumi npm run check:ech`。这是实时网络诊断，不属于离线测试；ECH 分类请求失败时退出码为 1。ECH 成功协商不代表上游一定及时响应，分类超时仍可能出现在握手完成之后。

## 常见问题

**网页能打开，番剧或规则列表加载失败？** 本地资料模式下，先在「偏好设置」查看首次导入是否完成及最近更新错误；已导入的分类、搜索、详情、近期热门和日历不依赖上游接口。归档下载和规则仓库仍需要服务器访问 GitHub；未缓存封面需要服务器访问 Bangumi。浏览器可以联网不代表 Docker 容器可以访问同一服务。

**能看到剧集，但视频不能播放？** 查看播放器显示的解析或播放错误。服务端会尝试动态 MP4/HLS 解析；验证码、源站限制或不支持的编码仍可能导致失败。可重新解析、换线或打开原站。本地开发提示浏览器未安装时，运行上面的 Chromium 安装命令。

**Mac 能播，iPhone/iPad 黑屏或转圈？** 更新部署后重新打开剧集，让视频通过服务端解析和同源代理。DM84 的 HHJX 和 7sefun 的 ndx 线路保留快速适配，其他网页线路会尝试浏览器解析。若关闭动态解析而回退到「来源站点播放器」，视频仍由设备直连第三方站点，可能受设备网络和源站限制。

**换设备后没有追番和历史？** 确认设备连接的是同一部署，且服务器使用原来的数据目录或数据卷。旧版数据保存在原浏览器中，需要在原浏览器的「偏好设置」点击「迁移浏览器旧数据」，或恢复先前导出的 JSON 备份。迁移完成后，清理浏览器数据不会删除服务器记录。

**规则数据丢失？** 确认使用同一 Compose 项目名及其数据卷。不要执行 `down -v`。可从先前导出的规则恢复。
