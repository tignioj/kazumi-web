# Kazumi Web

React + Node.js 网页端，兼容 [Kazumi](https://github.com/Predidit/Kazumi) 的 XPath / API 9 规则，支持 Docker Compose 部署。本地执行规则、搜索和章节解析；静态提取优先，动态播放器与验证码按需使用 Chromium。网页播放使用 ArtPlayer 与 hls.js。

接口、上游地址、缓存策略和存储位置见 [API 与持久化](docs/api.md)。实现边界、官方对照及性能复现见 [本地规则引擎](docs/local-rule-engine.md)。

`main` 是默认开发和发布分支，使用本地规则引擎（原 `codex/local-rule-engine`）。原先直接调用官方 Kazumi 核心的 `main` 保留为 `codex/upstream-core`，供历史参考；后续功能、修复和正式版本均以 `main` 为准。

## 部署

```bash
docker compose up -d --build --remove-orphans
```

打开 <http://localhost:3000>，其他设备使用 `http://服务器IP:3000`。Compose 只启动 `kazumi` 一个服务，镜像包含 Chromium headless shell、ECH 和原生 HLS 工具，不安装 Flutter 或官方 Kazumi 应用。

`kazumi-data` 沿用已有规则、收藏、历史、网络设置、图片、下载、番剧资料和评论缓存。升级时 `--remove-orphans` 停止旧 `kazumi-core` 容器；旧 `kazumi-core-data` 卷保留，可自行归档。日常停止使用 `docker compose down`，不添加 `--volumes`。镜像发布和预构建镜像部署见 [Docker Hub 镜像](docs/docker-publish.md)。

## 使用

1. 在「发现」「番剧分类」「放送日历」浏览番剧，或直接搜索片源。
2. 在「规则管理」新建规则、导入 JSON / kazumi 分享文本，或从官方目录安装、更新规则。
3. 搜索片源、选择剧集。本地引擎执行 XPath/API 规则，动态播放器需要时启动 Chromium；图片验证码、自动点击和规则验证脚本沿用规则配置。
4. 使用 ArtPlayer 播放、调整进度、倍速、全屏和画中画。选集、自动下一话及服务器观看记录由网页衔接。
5. 缓存当前剧集或批量缓存线路；支持暂停、继续、重试和删除，已有缓存继续可用。

片源搜索最多同时请求 4 个来源，完成一个就开始下一个，并立即显示结果。整体搜索超时或手动停止后保留已收到的结果；验证码暂停整体超时计时，验证后继续。连接中断或连接超时自动重试一次；证书、响应超时、HTTP 和解析错误显示具体原因。失败来源可单独重试，保留其他结果。

播放器仍受浏览器编码支持限制，站点可用性取决于规则与网络。手动验证只传送画面和有限的用户操作，Cookie 留在服务端。

## 维护边界

```text
React → Node 接口 → 本地 XPath / API 引擎
                 → 静态视频提取 → 按需 Chromium 嗅探 / 验证
                 → 同源媒体代理 → hls.js / 原生 FFmpeg + MediaSource → ArtPlayer
```

我们维护规则协议、浏览器适配和 Web 传输。官方 Flutter 应用只在 [开发对照目录](test/reference/kazumi-core) 中作为固定版本的测试参考，生产启动、构建和镜像发布均不依赖它。兼容样本记录官方实际输出和请求参数，普通测试离线验证；独立 `Official rule compatibility` 工作流与真实官方服务比较。

HLS 在线去广告使用 Kazumi 原生播放器的 FFmpeg `hls_ad_filter` 补丁，按实际视频包的 PTS 判断。构建时从官方仓库下载固定版本的 FFmpeg 和补丁并校验 SHA-256，原样应用，不维护 JS/Dart 广告算法或来源目录特例。服务器边读取边过滤，以 `-c copy` 转封装成浏览器可播放的分片 MP4，不重新编码、不等待整集完成，也不写整集临时文件。拖动和续播从目标位置重新读取，关闭播放器会取消请求并释放原生进程。

启用规则的 `adBlocker` 后，网页通过 MediaSource 播放原生过滤后的流，仍受浏览器编码支持限制。未启用的来源继续使用 hls.js 或浏览器原生 HLS。原生处理最多同时运行 4 个进程，满额或工具缺失时会报告错误。

规则请求和 Chromium 使用相同的视频网络分流、DNS 校验与私网限制。元数据、规则仓库、图片和归档保留各自的网络设置。验证码 Cookie 按浏览器访问者隔离，媒体链接只携带服务端会话标识。

目标实际走代理时允许证书校验失败；直连与重定向后的直连目标保留正常校验。镜像继续验证并安装 [公共中间证书](server/certificates/README.md)，供 Node 和 Chromium 使用。Chromium 默认在无任务 30 秒后关闭，已验证的访问者 Cookie 会话保留在 Node 内存中。

### 规则编辑器

在「规则管理」点击「新建规则」，或在已安装规则卡片点击「编辑规则」。表单按基本信息、搜索、章节、播放与请求、验证码分组，支持 XPath 和 API JSON 配置，以及请求头、参数、播放页模板和验证码脚本。

可随时切换到「JSON 编辑」修改完整规则；切换时保留额外字段和未启用的高级配置，JSON 格式错误时保留输入并显示原因。「检查兼容性」仅校验配置，不保存、不请求来源站点；保存时服务端也会校验。可以导出未保存的 JSON 草稿，关闭有修改的编辑器时会提示。新建规则不覆盖同名规则，批量导入仍沿用原来的合并行为。规则保存后由所有设备共享。

「规则测试」使用当前未保存的草稿实际请求片源：输入关键词测试搜索，点击结果解析章节，查看各条播放线路的剧集，再选择剧集「测试播放」，查看解析日志并在编辑器内试播。也可直接输入详情地址、API 来源值或播放页地址单独测试；各阶段只检查所需配置，保存时仍校验完整规则。支持 XPath / API 9，验证码、代理、动态解析和 HLS 去广告沿用实际播放流程。测试不保存规则、观看记录或视频缓存；遇到空结果、解析失败或播放失败会显示原因。可随时停止测试；离开测试页或关闭编辑器会停止未完成的请求和试播，修改草稿后清除旧测试结果。

### 上游跟进与兼容性升级

`Check Kazumi upstream updates` 每天北京时间 09:17 分别检查官方稳定版本、主分支关键代码和官方规则仓库。稳定版和 main 使用相同的 Web 相关性策略：比较完整 Git 树中的规则引擎、网络、视频解析、验证码及共用工具代码，并逐项比较相关依赖的约束、覆盖配置与锁定版本/来源/SHA。纯原生 UI（例如进度条、主题、图标）、开发工具及单独的版本/SDK 声明变化不会创建升级 PR。新增、删除和超过 compare 文件上限的关键代码仍会被发现；忽略的文件和依赖写入工作流摘要。规则更新下载同一固定提交的完整 JSON 目录，在 PR 中列出新增、修改、删除及字段前后差异；版本号不变的规则内容修改也会被发现。

每类更新至多保留一个待审查 PR，待审期间仍只读检查后续变化并写入工作流摘要，不覆盖维护者修改，也不重复提出已关闭的同一提交。PR 描述列出上游提交、源码差异摘录、依赖前后值和待核查的 Web 行为，并说明只更新测试参考时对线上没有直接影响。参考升级固定官方提交、锁文件、Flutter SDK 和参考 API；本地引擎 API 等级由实现决定。机器人显式派发 `Verify` 和 `Official rule compatibility`，后者比较规则请求、结果、动态播放和验证码行为。维护者审查上游差异、补充固定响应样本、移植相关修复，并在两边一致后显式更新 golden；测试通过后经 PR 审查合并，不自动合并。策略范围和维护方式见[本地规则引擎](docs/local-rule-engine.md#主分支规则快照与审查)。FFmpeg 及补丁按 `native/hls/README.md` 独立升级。

```bash
node scripts/update-kazumi.mjs
node scripts/update-kazumi.mjs --source main
node scripts/update-kazumi.mjs --source rules
node scripts/update-kazumi.mjs --verify
```

以上检查默认只读，工作流使用 `--write` 准备 PR。需要仓库允许 Actions 创建 PR；维护者应在分支保护中要求审查，以及 `Verify` 和官方兼容性检查通过。

## 本地开发与验证

需要 Node.js 24；本地 HLS/ECH 构建另需相应原生工具链，见 `native/`。

```bash
npm ci
npx playwright install chromium
npm run dev
npm run check
npm run test:compat:browser
npm run test:e2e
```

`npm run check` 包含普通回归和固定官方输出测试。无需运行 Flutter。`npm run test:compat` 可单独执行兼容性样本；真实官方比较与 Docker 性能对比的步骤见 [本地规则引擎](docs/local-rule-engine.md)。

## 本地番剧资料

默认从 [Bangumi 官方归档](https://github.com/bangumi/Archive) 建立本地 SQLite 动画及章节数据库，支持名称、别名、标签、年份和季度搜索筛选。首次启动后台导入，之后默认每 24 小时检查更新；「偏好设置 → 本地番剧资料」可查看状态和手动更新。

```bash
docker compose exec kazumi npm run metadata:update -- --status
docker compose exec kazumi npm run metadata:update
```

查询优先使用本地资料；首次导入未完成、本地读取失败或详情未收录时，自动回退到在线 Bangumi API，沿用 API 代理及 ECH 设置。导入完成后的新请求自动使用本地资料，无需重启。更新失败继续读取旧资料。`METADATA_AUTO_UPDATE=false` 关闭自动更新；`METADATA_MODE=remote` 使用远程 Bangumi API。封面经过同源图片缓存，与原有数据卷兼容。

详情页「番剧讨论」提供 Bangumi 短评和按集选择的剧集评论（含回复）；播放页下方可展开「剧集评论」。播放源名称中有明确集数且与 Bangumi 正篇唯一匹配时自动选中，否则手动选择对应剧集。评论只读，可通过链接前往 Bangumi 查看或参与讨论。

评论通过 Bangumi Next API 获取，与本地归档模式独立，沿用「Bangumi API 请求代理」及 API ECH 设置。短评按页缓存；剧集评论由上游一次返回全部讨论及回复，在本地分页。已获取的数据持久保存在 `DATA_DIR/comments/comments.sqlite`（Docker 的 `kazumi-data` 卷），重启和更新元数据后仍可读取。默认缓存 30 分钟，过期或点击「刷新评论」时重新获取；网络失败时继续显示旧缓存和更新时间，未缓存的页面提示重试。首次获取和更新仍需访问 Bangumi。

`COMMENTS_CACHE_TTL_MINUTES` 设置有效时间（默认 `30`，大于 0）；`COMMENTS_CACHE_MAX_BYTES` 设置缓存内容容量（默认 `52428800`，即 50 MiB，大于 0）。超过容量或 2000 个缓存条目时淘汰最早更新的内容；SQLite 复用已分配的磁盘空间。完整迁移时随数据目录或数据卷备份。`BANGUMI_NEXT_URL` 可覆盖上游基址；评论缓存按上游地址隔离。

## 视频下载与缓存

- 打开剧集，完成 MP4/HLS 解析后点击缓存按钮。任务由服务端执行，关闭网页不影响下载；同一来源、同一剧集不会重复创建任务。
- 「选择剧集缓存」支持勾选指定剧集、全选及取消全选，显示已选数量和各集缓存状态。点击「缓存所选」将选中的剧集加入服务端队列，逐集解析并缓存，关闭网页后仍会继续。已完成或正在排队、下载的剧集不可重复选择，缓存失败的剧集可重新勾选；单集失败不影响后续任务，失败原因在「下载缓存」中查看。一次最多加入 200 集，并受现有任务数量和总容量限制。
- 「下载缓存」将同一番剧、同一片源的剧集归入可折叠的列表，按集数排列，并汇总缓存数量、下载状态和占用空间；每集仍可查看进度、播放、保存到设备或删除，也可清理全部缓存。删除进行中的任务会取消下载并释放已写入的文件；不会清除规则、收藏或观看记录。
- 下载列表和播放器缓存面板提供「暂停下载 / 继续下载」。排队或正在解析、下载的任务均可暂停，暂停后停止请求、释放下载名额，保留普通视频的已下载字节和 HLS 已完成的文件，进度仍计入缓存容量。暂停状态跨刷新和服务重启保留，只有点击「继续下载」才重新加入队列；删除任务会清除进度。源站不支持范围请求或没有文件版本标记时，继续下载会重新读取并比对已保存内容，再写入剩余数据，因此仍可能重复传输部分网络流量。
- 点击分组标题旁的「删除整组」，确认后一次删除该剧在当前片源下的全部缓存及任务，并取消组内排队或正在下载的任务；其他番剧、其他片源的缓存会保留。
- 从缓存列表播放任意一集时，播放器会带上同组已缓存完成的剧集，按集数提供选集和「下一话」；开启「自动播放下一话」后可连续播放。排队、下载中或失败的任务不加入播放列表。
- 缓存保存在 `DATA_DIR/downloads`，由访问同一部署的设备共享。已完成任务在服务重启后仍可播放，直接从「下载缓存」进入无需访问原站或保留来源规则。网页仍需连接部署服务器，这不是浏览器离线应用。
- 普通视频可下载原文件到设备。HLS 点播会保存播放清单、子清单、分片、初始化资源和 AES-128 密钥，导出为 `.tar.gz` 文件；解压后使用支持本地 HLS 的播放器打开根播放清单，不会合并或转码为 MP4。含多个清晰度或音轨的清单会缓存其引用的资源。
- HLS 缓存保存原始分片和规则的去广告标记，站内回放使用同一套原生 PTS 过滤。导出的压缩包保留源视频包，可能包含广告；由外部播放器决定是否过滤。旧版本已经删除的正文分片无法自动恢复，需要删除对应缓存后重新下载。
- 支持 DM84 等来源以图片类型返回、带图片文件头的 HLS 分片，缓存及导出会保留原始字节，站内缓存播放沿用 hls.js 兼容处理；上游返回的网页、JSON 和 SVG 等错误内容仍会被拒绝。
- 在「偏好设置 → 视频下载与缓存」可设置单集下载线程数（1–8，默认 4）。普通视频先探测范围请求，支持时按字节范围并行下载；源站不支持或忽略范围请求时自动改用单连接。HLS 按分片、密钥和初始化资源并行下载，保留清单中的顺序及引用。保存后新开始和重试的任务生效，已在下载的任务继续使用原设置。设置由所有设备共享，保存在 `DATA_DIR/downloads/settings.json`，重启后保留。
- 普通视频在源站支持范围请求并提供强 ETag 或 Last-Modified 时保留字节进度，HLS 保留已完成且通过校验的文件。下载失败或服务重启后，在「下载缓存」点击「继续下载」，会重新解析来源、核对文件版本或 HLS 清单并续传；也可重新选择该集缓存。来源地址、文件版本或清单变化时安全地重新下载。源站不支持续传时重试会从头下载；未完成任务不会作为完整缓存播放，取消或删除任务会清除续传文件。媒体地址和认证信息不会写入续传索引。
- 暂不支持直播、DRM、DASH 和来源站点 iframe 播放器。
- 默认缓存总容量为 10 GiB，同时下载最多 2 集，每集使用所设置的线程数。续传文件也计入容量，达到容量限制时任务会显示失败原因，可先手动清理，再重新缓存。可通过 `VIDEO_CACHE_MAX_GB` 按 G 调整容量上限（1 G = 1 GiB = 1024³ 字节，支持小数，例如 `1.5`）；不会自动删除已有缓存。

设置中的 JSON 数据备份不包含视频文件。迁移完整缓存时，停机后备份并恢复数据目录或 Docker 数据卷。

## 收藏、历史与播放进度

- 收藏状态和最近 200 条观看记录保存在 `DATA_DIR/watch-data.json`，与规则、视频缓存共用持久化数据目录。更新代码后重新构建即可，无需新增数据库或环境变量。
- 所有访问同一部署的设备共享一份记录。打开页面、切回页面以及页面可见时每隔 15 秒读取服务器记录；播放进度每隔约 5 秒保存，暂停、切换剧集、退出播放器和关闭页面时也会尝试保存。读取或保存失败会显示提示。
- 旧版浏览器数据不会自动覆盖服务器。打开原浏览器的「偏好设置」，点击「迁移浏览器旧数据」：新增缺少的收藏，保留服务器已有的收藏状态；同一片源的观看记录按更新时间保留较新的一条。服务器确认保存后才删除对应的浏览器旧数据；迁移失败时原数据保留。
- 「恢复备份」会覆盖服务器的收藏和观看记录，以及本机的界面偏好；「清空记录」会清空服务器的观看记录。这些记录变更会影响连接同一部署的所有设备，界面操作前会提示。

## 网络设置

在左侧导航的「代理设置」（`#/proxy`）配置默认代理及最多 16 个额外代理出口，偏好设置中也保留入口，旧网络设置链接会跳转至此。填写完整的 HTTP、HTTPS 或 SOCKS5 地址，例如 `http://127.0.0.1:7890` 或 `socks5://127.0.0.1:1080`。各出口分别保存名称、地址、用户名与密码。五类请求各有默认开关和代理选择，没有全局代理开关：

- 「视频源请求代理」：片源搜索、剧集解析、视频流、视频缓存下载，以及动态解析和人工验证浏览器中的请求。右上角「视频默认代理」快捷开关仅控制这一类的默认策略，立即保存，自定义规则仍优先。
- 「番剧图片请求代理」：Bangumi 原图、wsrv.nl 图片镜像及封面地址查询；不受视频或 API 代理开关影响。
- 「Bangumi API 请求代理」：评论及远程资料模式下的分类、搜索、详情、章节、日历等 Bangumi API 请求；代理关闭后按 API ECH 开关连接。本地资料查询不访问 Bangumi API。
- 「规则仓库请求代理」：官方规则目录、规则安装和规则更新，包括 GitHub 原始文件及重定向后的地址。
- 「资料归档下载代理」：官方归档版本检查和 ZIP 下载，适用于自动更新、网页手动更新和 `npm run metadata:update` 命令行更新。

「自定义分流规则」最多保存 200 条。每条可选择五类中的一种或全部类型，匹配精确域名、域名及子域名、域名关键字、IP 网段，或该类型的全部请求，再指定某个代理出口或「应用直连」。从上到下首次命中，优先于默认开关；未命中时沿用该类型的默认设置。支持启停、上移、下移和删除。IP 网段仅匹配 URL/CONNECT 目标本身是 IP 的请求，不对域名的 DNS 结果二次匹配。HTTPS 仅按主机匹配，不解密 URL 路径。

从已安装片源生成规则时，读取其当前主站、搜索和章节 API 的域名，生成可编辑的域名及子域名条目。片源名称不用于猜测未知 CDN；播放器、验证页面、分片和下载的其他域名可另加规则，片源升级改变域名后也需调整对应条目。例如可将 `agedm.io` 设为应用直连，将 `lmm85.com` 和 `sbdl.cc` 设为你的直连代理出口。

「应用直连」仅表示不使用本应用配置的显式代理，仍可能被系统、OpenClash TUN 或路由器策略接管；出口是否出国由外部网络配置决定。代理出口名称可自行标注为「OpenClash 直连」「规则代理」等。

点击「保存代理设置」后新请求立即生效，无需重启，已有连接可能继续使用原设置。五类开关默认关闭；旧代理配置保留为「默认代理」，升级后不自动添加分流规则。重定向和 CDN 请求保留原请求类别，并按每一跳的实际目标主机重新匹配。所选代理不可用时会报错，不会自动切换到其他出口。

「封面请求方式」可单独选择「镜像 / ECH / 直连」：镜像将 Bangumi 图片 URL 改写为 `https://wsrv.nl/?url=<编码后的原域名、路径和查询参数>`，GIF 追加 `n=-1` 保留动画；ECH 使用原图片 URL 并加密握手，封面地址查询也使用 ECH；直连使用原图片 URL 和普通 HTTPS。新安装默认直连，升级时按旧的 Bangumi ECH 开关保留原封面方式，此后 API 和封面设置分别保存，互不联动。切换方式继续复用已有缓存，未缓存图片及后续刷新使用新方式。分流至代理的图片请求优先使用对应代理，ECH 模式此时由普通代理通道代替；镜像请求按实际目标 `wsrv.nl` 匹配。

「查看分流」按当前表单和测试 URL 预览目标主机、命中的规则或类型默认策略，以及所选出口，不建立连接或保存设置。「测试连接」使用同一套匹配逻辑发送实际请求，成功及失败时均显示出口和命中依据，成功还显示 HTTP 状态与耗时。重定向后的结果显示最后一跳策略。各类型分别保留自定义测试地址；视频源需填写源站或视频地址，其余类型提供默认地址。API 测试遵循 API ECH 开关，图片测试遵循封面方式，归档默认请求版本接口，不下载完整 ZIP。各代理密码均不会通过设置接口回传；保持密码框未修改可保留原密码，点击「清除已保存密码」后保存会清除对应密码。删除被默认策略或分流规则引用的代理前需先调整引用。

代理、API ECH 和封面请求方式由所有设备共享，保存在 `DATA_DIR/network-settings.json`，服务重启后保留；不包含在浏览器 JSON 数据备份中。`npm run metadata:update` 读取已保存的资料归档代理开关及认证配置。浏览器直接打开的原站链接、iframe 播放器及外部图片仍使用访问者自身网络。

代理地址从应用服务器访问：Docker 内的 `127.0.0.1` 指向容器自身。Docker Desktop 访问宿主机代理可填写 `host.docker.internal`；Linux Docker 需在 Compose 服务中添加 `extra_hosts: ["host.docker.internal:host-gateway"]`，并确保宿主机代理监听容器可达的地址。容器之间也可通过同一 Docker 网络中的服务名连接代理。

目标站点仍沿用现有 URL、DNS 与重定向校验：先在服务器解析并校验目标地址，再将选定的 IP 交给代理，保留原始 HTTP Host 和 HTTPS TLS 校验。默认继续拒绝私网目标；配置的代理服务器本身允许使用本机或局域网地址。DNS 查询继续使用服务器 DNS 或已配置的 DoH，并不交给代理解析。

## 配置

复制 `.env.example` 为 `.env`，可调整端口、监听地址、缓存容量、图片缓存和归档更新设置。Compose 已包含动态解析所需的 Chromium；本地运行及高级环境变量见 `.env.example`。
